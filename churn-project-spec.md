### Phase 1 — Cleaning → `01_clean.ipynb`, `src/clean.py`
Apply these steps **in this order** and record a cleaning log table: `step | rows_before | rows_after | removed | pct_removed | reason`.
1. Drop rows with null `Customer ID`. Reason: revenue can't be attributed to a customer.

### Phase 2 — SQL analysis in DuckDB → `02_sql_analysis.ipynb`
Write each query as a visible SQL string executed with `duckdb.sql(...)`:
1. Monthly revenue, order count, and active customers. **Chart:** monthly revenue line.
2. Top 10 countries by revenue, with % of total.
3. **Top 3 products per country** by revenue, using `ROW_NUMBER() OVER (PARTITION BY Country ORDER BY revenue DESC)`, shown for the top 5 countries.
4. **Revenue concentration:** % of revenue from the top 1%, 10% and 20% of customers (window functions or `NTILE`). **Chart:** cumulative revenue share vs customer percentile (a Lorenz-style curve).
5. Average order value by month.
6. **Month-over-month retention:** % of customers active in month *m* who buy again in month *m*+1.

### Phase 3 — RFM segmentation → `03_rfm.ipynb`
1. Snapshot date = max `InvoiceDate` + 1 day.
2. Per customer: Recency (days since last purchase), Frequency (distinct invoices), Monetary (total revenue).
3. Scores 1–5 via `pd.qcut`. Recency is reversed (most recent = 5). Use `rank(method="first")` before `qcut` for Frequency to handle ties.
4. Segment rules (document them in the notebook):
   - Champions: R≥4, F≥4
   - Loyal: F≥4, R≥3
   - Potential: R≥4, F≤3
   - At-Risk: R≤2, F≥3
   - Hibernating: R≤2, F≤2, M≥3
   - Lost: everyone else with R≤2
   - Other: remaining
   Adjust only if a segment ends up empty or absurd, and note any change.
5. Table: `segment | customers | pct_customers | revenue | pct_revenue | avg_recency | avg_frequency`.
6. **Chart:** % customers vs % revenue by segment (grouped bars).
7. **Verify:** pick 2 random customer IDs and recompute R, F, M directly from `clean.parquet` with plain pandas. Assert they match.

### Phase 5 — Churn model → `04_churn_model.ipynb`, `src/features.py`
**Churn definition:** a customer who was active before the cutoff churns if they make **no purchase in the 90 days after the cutoff**.

`build_features(clean_df, cancel_df, cutoff)` uses **only data before the cutoff** and returns X and y for customers with at least 1 purchase in the 365 days before the cutoff.
Features: recency, frequency, monetary, tenure (days since first purchase), avg order value, distinct products, return rate (from cancellations), days between orders (mean), and is_UK.

**Time-based validation (no random split):**
- Train: cutoff 2010-09-01, label window through 2010-11-30.
- Test: cutoff 2011-09-01, label window through 2011-11-30.
- Explain in a markdown cell why a random split would leak future information.

**Models:**
1. Baseline: recency alone as the score.
2. Logistic regression in a `Pipeline` with `StandardScaler` (`class_weight="balanced"`).
3. `HistGradientBoostingClassifier` with default parameters, plus light tuning only if it is clearly underfitting.

**Report:** a table with `model | ROC-AUC | PR-AUC | precision@top10% | recall@top10%` on the TEST set, the churn base rate in train and test, logistic regression coefficients (standardized) with a one-line business interpretation each, and a ROC curve chart comparing all three.

**Verify:** assert no feature uses dates ≥ the cutoff. Assert the train and test customer counts are printed. If the model improves on the baseline by less than 0.03 AUC, say so and explain why.
